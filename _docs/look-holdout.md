# いつまで登録すれば読めるようになるか（見た目の判定の作り直し）

2026-10-10 に「履歴の上限を 100 → 200 → 300 と上げてきたが、局面の登録はいつまで続ければいいのか」
という問いから出てきた課題。**まだ手を付けていない**（`TODO.md` の「学習データ・運用」から引いている）。

## 結論

**今の仕組みでは「いつ終わるか」に答えられない。** 終わりを判断する物差し（見た目ホールドアウト）が、
8 月以降に集めた局面を見ていないため。物差しを作り直してから、曲線の傾きで止めどきを決める。

## 今どうなっているか（2026-10-10 の実測）

| | 件数 |
|---|---|
| 保存済み局面 | 238 |
| 見た目の名前が付いた局面 | **83**（16 通り）|
| 名前の無い局面 | **155**（うち ikkyoku から API で来たものが 127）|

- **見た目ホールドアウトは名前の無い局面を学習にも評価にも使わない**
  （`training/evaluate.go` の `holdoutPredictors`。key が空なら飛ばす）
- そのため、評価タブの「見た目LOO」は **8/21 から「83 局面 / 16 見た目」の母集団で止まっている**。
  `data/accuracy.json` で値が動いたのはコードを変えたときだけ（10/10 の k=1 で 全マス 92.3%・駒種 81.7%）
- **100 → 200 → 300 と集めた分が「初めて見る盤」の成績に効いたかは、一度も測れていない**
- API で来た 127 件が同じ中継の繰り返しなら、それは種類ではなく厚み。判定しないと分からない

## 何が悪かったか

**人に答えられない判定を求めていた。** 見た目タブは「同じ見た目（＝同じ駒・同じ盤・同じ画面）か」を
人に決めさせる作りだが、**別の対局どうしは画像を見ても「似ている」としか言えない**。同じ駒かもしれないし、
違う駒かもしれない。そのうえ AGENTS.md の「名前は『対局』ではなく『画面の見た目』で付ける」で、
対局名で付けていたことを注意する形になっていた。

一方で、**同じ駒かどうかを決める材料はデータ側に既にある。** AGENTS.md の朝日杯の行列
（`TestLookGroupingCheck`）は「相手 1 局面を学習データにして読んだときの一致率」で、
別の対局でも同じ画面なら同じ対局と同じ高さに出て、別の画面とは 15〜20pt 落ちる。
**これは機械が測れる。人の目に頼る必要が無かった。**

画面も使いにくい（判定の作業が 8 月から進んでいないのはこのため）。

## 作り直しの案

### 1. 人がやる判定は「同じ対局・同じ画面か」だけ

- 確信を持って答えられる問いにする。実盤と大盤のように画面が変われば別、はすぐ分かる
- 対局名をそのまま付けてよい（今までの 83 件の付け方はそれで正しい）

### 2. 対局どうしを束ねるのは機械

- 対局 A・B について「B を学習データにして A を読んだ一致率」を測る（`TestLookGroupingCheck` と同じ）
- **同じ対局で測った値と変わらなければ、同じ駒とみなす**
- 見た目ホールドアウトは「その対局 + 機械が同じ駒とみなした対局」を丸ごと学習から外す
- 決めること: 「変わらない」の幅（同じ対局どうしの値のばらつきから決める。手で置かない）、
  束ね方（完全連結か。`proposeLooks` は連鎖を避けて完全連結にしている）

### 3. 判定の手間を無くす

- **これから来る分**: ikkyoku は追従の録画ごとにディレクトリを分けている
  （`%APPDATA%\ikkyoku\captures\follow\20261006-122723\` など）。`/api/register` にその単位
  （録画 ID）を任意の項目で送ってもらえば、人が何もしなくても「同じ対局」が付く
  （ikkyoku 側の変更が要る）。⚠️ 同じ録画の中で画面が切り替わる（実盤 → 大盤）ことはあるので、
  録画 ID は「同じ対局」の候補であって、画面の違いは 2 の測定で分かれる
- **既にある 155 件**: 撮影時刻が近く署名も近いものを機械が「同じ対局らしい」塊にしておき、
  人は「合っている / 分ける」を押すだけにする。⚠️ 時刻だけでは同じ放送の中の別の画面が混ざる
  （AGENTS.md「盤の見た目ごとの厚み」の実測）ので、署名と組み合わせる

### 4. 止めどきの決め方

判定が入ったら、学習に使う「束ねた見た目」の数を 1・2・4・8・16・32・全部と増やして、
初めて見る盤の成績と誤りの内訳を測る（`TestVarietyVsThickness` を全部まで延ばす）。
次のどちらかで止める:

1. 見た目の数を倍にしても、初めて見る盤の成績がほぼ上がらない（目安 1pt 未満）
2. 残る誤りの大半が、データを足しても直らない種類になった
   （被覆率で決まる空判定・向きの残り・盤面検出）

10/10 時点の見た目LOO の誤り 519 マスは、駒種違い 459・向き 46・空→駒 9・駒→空 5。
**駒種違いはデータで直る側**なので、2 の基準ではまだ終わりではない（ただし 16 通りの範囲の話）。

**履歴の上限 300 は資産を守る歯止めで、集める目標ではない。** 測るまでは上げない。
