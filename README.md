# suteme

将棋盤の画像から盤面を認識して SFEN を出力する Pure Go のライブラリ。

```go
sfen, err := suteme.LoadSFEN(img)
// "lnsgkgsnl/1r5b1/ppppppppp/9/9/9/PPPPPPPPP/1B5R1/LNSGKGSNL"
```

外部の画像処理ライブラリや機械学習フレームワークには依存しない。盤面の検出も
駒の分類も標準ライブラリの `image` の上に自前で書いてある。駒種の判定にだけ
学習データを使う（既定は k-NN。学習処理は不要）。

将棋の仕様（SFEN / USI / KIF）は [`core`](https://github.com/ShinteLab/core) に
一本化していて、suteme は自前の変換を持たない。

---

## できること・できないこと

| 画像 | 盤面検出 | 駒種の認識 |
|---|---|---|
| ゲーム画面（真正面） | ◎ | ◎ 推奨 |
| 実物の盤を撮った TV 中継画像 | ○ | △ 成駒は人間でも判別しづらい |
| 写真（斜め撮影） | × | × 射影変換が未実装 |
| 駒の形を描かず文字だけの盤 | ○ | × 空判定・向き判定の前提が崩れる |

- **駒台（持ち駒）の画像認識は未実装。** 盤上の駒数から逆算した不足分を、
  便宜的にどちらかの駒台へ寄せることはできる（`WithHandTo`）。
  学習用サーバでは解析タブから手入力できる
- **手番は画像からは決まらない。** `Result.SFEN()` はオプションで与えた値を書くだけ。
  画面ごとに表現が違いすぎるので、手番と手数の認識は実装しない方針
- **「手前が先手」で固定する（規約）。** 駒の向きから分かるのは「どちらの対局者の駒か」
  だけで、その人が先手か後手かは盤の絵に写っていない（中継・紙面は「手前が先手」だが、
  ゲーム画面では自分が後手番のとき手前が後手になる）。**原理的に解けないので解かない。**
  実際の対局で後手が手前でも、**手前側を先手として扱った SFEN が返る**。
  必要なら呼び出し側で読み替える
- **駒数の検証は参考情報であってエラーではない。** 正しいのは画像であり、
  **駒落ちや詰将棋では駒が少ないほうが正常**。多すぎる場合だけが認識の誤りを示す
- **学習データが要る。** リポジトリにはモデルも学習データも含まれていない
  （`.gitignore` で除外）。後述の学習用 Web サーバで自分の画像から作る

## インストール

```bash
go get github.com/ShinteLab/suteme
```

`core` はまだタグを打っていないため、`go.mod` が相対パスの `replace` で参照している。
**`suteme` と `core` を同じ親ディレクトリに並べて置くこと。**

```
shinte/
├── core/
└── suteme/
```

## 使い方

### 画像 → SFEN 盤面文字列

```go
img, _, _ := image.Decode(f)

board, err := suteme.LoadSFEN(img)
if err != nil {
    log.Fatal(err)
}
fmt.Println(board) // '/' 区切りの9段。手番・持ち駒・手数は付かない
```

`LoadSFEN` が返すのは**盤面部分だけ**。suteme の責務を「画像 → 盤面」に閉じてある。

駒種の推論器はカレントディレクトリ、次に実行ファイルのディレクトリから自動で読む
（`training_data_v6.bin` があれば k-NN、無ければ `model_v6.json` の NN）。
見つからなければ `ErrNoPredictor` を返す。

### 駒数の検証・持ち駒の推定まで

```go
r, err := suteme.Recognize(img,
    suteme.WithErrorOn(sfen.CheckPieceCount|sfen.CheckKing), // 駒数が合わなければエラー
    suteme.WithHandTo(suteme.HandBlack),                     // 足りない駒は先手の駒台へ
    suteme.WithTurn(true))

// **エラーを返すときも Result は返る**ので、どこがおかしいかを画面に出せる
for _, w := range r.Warnings() {
    fmt.Println(w) // 「歩が19枚あります(上限 18枚)」など
}
fmt.Println(r.SFEN()) // "lnsg... b 2R2B4G4S4N4L18P 1"
```

エラーは `errors.Is` で判別する。

| | |
|---|---|
| `ErrBoardNotFound` | 盤面を検出できなかった（信頼度が閾値未満） |
| `ErrNoPredictor` | 駒種の推論器が見つからない |
| `ErrInvalidBoard` | 盤面の検証に違反があった（`errors.As` で `*BoardError`） |

**既定は「全部調べるが、エラーにはしない」。** 中継が盤を映していない・認識器が
外すのは異常ではない、という前提に合わせてある。厳しくするなら `WithErrorOn` /
`WithStrict`、一切エラーにしないなら `WithLenient`。

### オプション

| | |
|---|---|
| `WithPredictor(p)` | 推論器を指定（既定はファイル探索） |
| `WithRegion(br)` / `WithRect(x1,y1,x2,y2)` | 盤面領域を明示指定（検出を挟まない） |
| `WithChecks(c)` | 実施するチェック（既定 `sfen.CheckAll`） |
| `WithErrorOn(c)` | 違反をエラーとして返すチェック（既定は無し） |
| `WithStrict()` / `WithLenient()` | 全部エラーにする / 一切エラーにしない |
| `WithHandTo(side)` | 盤上に無い駒をどちらの持ち駒として扱うか |
| `WithTurn(black)` / `WithMoveNumber(n)` | `Result.SFEN()` が出力する手番・手数 |

### 盤面座標が分かっているとき

UI 上でドラッグして指定する場合など、座標が分かっているなら渡すほうが確実。
**手動指定の座標は検証せずそのまま使う**（機械が疑わない）。

```go
r, err := suteme.Recognize(img, suteme.WithRect(4, 1, 637, 703))
```

### 認識が外れたときに中を見る

画像と SFEN しか手元に無いと、盤面をどこだと思ったのか・どの推論器を使ったのかが
分からず、座標の問題か認識器の問題かを切り分けられない。`Result.Debug` は必ず入る。

```go
r, _ := suteme.Recognize(img)

fmt.Println(r.Debug)
// region=(4,1)-(637,703) cell=70x78 src=detect conf=1.00 predictor=knn(k=5, samples=5265) <- ./training_data_v6.bin

fmt.Print(r.Debug.Dump())        // 盤の形に並べた表記と確信度
r.Debug.LowConfidenceCells(0.6)  // 怪しいマスだけ絞り込む
```

`RegionSource` が領域の決め方（`option` / `detect` / `whole`）を示す。
**観測用であって認識の判断には使わない。**

## 学習データを作る（学習用 Web サーバ）

駒種の認識には学習データが要る。ラベル付けから学習までをブラウザで行う。

```bash
cd suteme
go run ./_cmd/suteme-training/ 8888
# http://localhost:8888
```

5 つのタブで工程を分けてある。

| タブ | すること |
|---|---|
| **入力** | 画像を貼る（D&D / Ctrl+V）→ 盤面検出 → 自動認識の結果を見る |
| **解析** | 盤面の手動指定・マス目のラベリング → 保存 |
| **履歴** | 保存済み局面を選んで学習 |
| **評価** | 保存済み局面の正解と突き合わせて認識率を測る（実行ごとに記録）|
| **API** | 外部からの訓練データ登録の設定（既定は無効）|

流れとしては、画像を貼る → 認識が合っていればそのまま「保存」（未入力のマスは
自動分類と推論候補で埋まる）→ 履歴タブで「全選択」→「学習」。
ズレていれば解析タブで盤面をドラッグ指定し、違うマスだけクリックして直す。

学習データは `training_data_v6.bin` に累積し、k-NN はそこから即座に構築される
（学習処理は要らない）。「学習」が数秒で終わるのはこのため。
ファイルは float32 のバイナリで、JSON だった v3 に比べて 178MB → 36.5MB・
読み込み 1.72s → 42ms（16605 サンプルでの実測）。
**版を上げたときは旧ファイルを読まない。** 学習データは履歴の画像と正解 SFEN から
全部作り直せるので、履歴タブで「全選択」→「学習」すればよい。

比較用の gobrain NN（`model_v6.json`）は**既定では訓練しない**。
訓練時間が累積サンプル数に比例して数十分かかるうえ、認識に使うのは k-NN だからで、
必要なときだけ履歴タブの「NN（比較用）も学習し直す」を付ける。
そのため `model_v6.json` は学習データより古いことがあり、画面では
「NN（学習データより古い）」と断って表示する。

### 認識率を測る（評価タブ）

**モデルや認識ロジックを変えたときに、良くなったのかを確かめるための口。**
保存済み局面の正解 SFEN と突き合わせて、実行 1 回を 1 行として
`data/accuracy.json` に積む。前回との差が表に並ぶ。

測るのは 3 系統で、**盤面検出も含む**。

| 系統 | 内容 |
|---|---|
| **検出** | 自動検出した外枠と、保存してある手動指定座標との差（マス単位）|
| **手動** | 座標を与えたときの認識率＝認識器そのものの成績 |
| **自動** | 検出から通した端から端まで。**検出できなかった局面は 0/81** |

**最終目標は手入力の座標なしで動くこと**なので、検出に失敗した局面も
（平均から外さずに）0/81 として数え、**棄却された候補の位置と信頼度も残す**。
「あの中継画像の盤が拾えるようになったか」を後から追えるようにするため。

「leave-one-out も測る」を付けると、局面ごとにその局面を学習から外して
k-NN を組み直したうえで測る（未知の局面に対する実力）。外すと数十秒で終わるが、
**評価する局面が学習済みなら高く出る**ので絶対値は信用できない。

実測（70局面 / 5670マス、22356 サンプル、leave-one-out 込みで 3.4 分）:

| | 全マス一致 | 駒マスの駒種 |
|---|---|---|
| 手動（学習済み込み）| 98.9% | 97.3% |
| 自動（学習済み込み）| 96.4% | 94.1% |
| **手動（leave-one-out）** | **94.7%** | 87.5% |
| **自動（leave-one-out）** | **92.7%** | 85.4% |

盤面検出は 68/70 が 0.5マス以内。

### どれだけ集めればよいか

**局面の数より「同じ出所（同じゲーム画面・同じ中継）が何枚あるか」が効く。**
実測（駒マスの駒種の正解率、未知の局面に対して）:

| 学習データ | 駒種 |
|---|---|
| 同じ出所 1 枚だけ | **87.8%** |
| 同じ出所 3 枚 | 95.0% |
| 同じ出所 5 枚 | 97.9% |
| 他所 全部（111枚）| 88.5% |

同じ出所 1 枚が、見た目の違う盤 111 枚に匹敵する。**新しい出所を読ませる予定があるなら、
その出所から 3〜5 枚ラベル付けするのが先。** k-NN は全件走査なので推論時間が
サンプル数に比例する点でも、出所ごとに絞るほうが有利。

### 外部から訓練データを登録する（API タブ）

盤面認識を通したデータを持つアプリから、学習用の局面を直接送り込める。
**既定は無効**で、API タブで有効にする。

```bash
curl -F image=@board.png -F sfen="lnsgkgsnl/..." \
     -F x1=4 -F y1=1 -F x2=637 -F y2=703 \
     -H "Authorization: Bearer <token>" \
     http://<host>:8888/api/register
```

| | |
|---|---|
| `GET /api/status` | 登録を受け付けられる状態か（**`/api/health` ではない**） |
| `POST /api/register` | 画像 + 正解 SFEN + 盤面座標（**必須**） |

送る SFEN は**手前側を先手として表現する**（上記の規約）。実際の対局で後手が
手前でも同じ。これを外すと学習データの向き正規化が狂い、その出所だけ上下反転した
サンプルができる。**機械には検出できないので送信側が守る前提。**

学習データは壊れやすい資産（手でラベル付けした正解であり、一度学習に通すと
履歴を消してもサンプルは残る）なので、次の約束を置いてある。

- **ループバック以外から触れるのは `/api/status` と `/api/register` だけ。**
  学習・削除・セッション系は公開設定に関わらず常にローカル限定
- **ループバックは認証を免除する**（同じサーバが配信している UI が認証を持たないため）
- **API 経由のデータは「未確認」として入り、学習には使われない。**
  画像と SFEN の対応は機械には検証できないので、解析タブで人が一度見て
  保存し直すまで通さない
- **履歴の上限（200 件）に達したら 507 で断る。古い局面は消さない**

## 仕組み

```
入力画像
  ↓ 盤領域の絞り込み（横線の線分抽出 → 端点のクラスタ）      segment.go
  ↓ 盤面検出（エッジ投影 → 等間隔10本選択 → 外枠の微調整）   detect.go
  ↓ 検証（背景色の均一性 × グリッド整合度）                  validate.go
  ↓ 空/先手/後手 の分類（画像処理のみ・学習不要）            classify.go
  ↓ 駒種の推論（k-NN。後手は180度回転して正規化）            knn.go
SFEN 盤面文字列 → 駒数の検証                                komadai.go → core/sfen
```

- **マスの縦横比は 1.09。将棋盤は正方形ではない**（規格 3.03寸 x 3.33寸）
- **向きは駒の五角形の形から決める**（外接範囲を上下に割り、幅の中央値が広いほうが底辺側）。
  確信度が低いマスだけ学習データとの回転照合に任せる
- **学習時に盤面座標をずらしたクロップも作る。** 検出座標は手動指定に対して数 px
  ずれるので、ぴったりの座標だけで学習すると k-NN がそのクロップを丸暗記する

実測:

| | |
|---|---|
| 分類器単体（空/先手/後手。118局面 / 9558マス）| 97.4% |
| 全マス一致（118局面、leave-one-out）| 95.0% |
| 駒マスの駒種（同上）| 88.2% |

**設計判断の根拠と実測値は [CLAUDE.md](CLAUDE.md) に全部書いてある。**
「なぜ正方形ではないのか」「なぜ分散で空判定してはいけないのか」といった、
戻すと壊れる箇所の記録が入っているので、手を入れる前に読むこと。

## 開発

```bash
go build ./...
go test ./...
go vet ./...
```

**精度の測定には `data/` の保存済み局面が要る。** リポジトリには含まれていないので、
学習用サーバでラベル付けしたものが手元に無いと該当のテストは測定をスキップする。

| テスト | 測るもの |
|---|---|
| `TestDetectBoardMatchesManual` | 盤面検出と手動指定座標の差 |
| `TestValidateBoardDiscriminates` | 正解の領域と歪めた領域を弁別できるか |
| `TestClassifyAccuracy` | 空/先手/後手 の分類精度 |
| `training.TestKNNHoldout` | 局面ホールドアウトでの認識精度 |
| `training.TestLearningCurve` | 学習局面数と精度の関係 |
| `training.TestSameSourceEffect` | 同じ出所を厚くしたときの効き |

`_cmd` 配下はアンダースコア始まりなので `go build ./...` の対象外。
学習サーバは `go run ./_cmd/suteme-training/` で起動する。
