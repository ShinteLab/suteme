保存済み局面の正解 SFEN と突き合わせて認識率を測り、実行ごとに記録します。 モデルや認識ロジックを変えたあとに実行すると、前回との差が下の表に並びます。
チェックを外すと起動中の推論器そのままで測ります。数秒で終わりますが、 評価する局面が学習済みなら高く出るので絶対値は信用できません（版どうしの相対比較には使えます）。
盤面なし画像（負例） — 盤が写っていない画像を置いておくと、評価のたびに 「盤として採用してしまわないか」を測ります。正解 SFEN も座標も要りません。
効くのは枚数ではなく中身です。本命は盤に似た格子を持つ絵（表・カレンダー・ターミナル・ 棋譜の一覧・罫線の並んだ UI パネル）で、無関係な写真は簡単に落ちるので情報量がありません。 10〜20 枚で十分です。入力タブで画像を開いて「この画像に盤面は無い」を押すか、 data/negative/ に PNG を直接コピーしても同じです。
盤の見た目の一覧 — 目標はどんな盤でも読むことなので、集めるのは 種類です。同じ見た目を積んでも目標には効きません（実測: 同じ 8 枚を 8 種類×1枚に散らすと 79.3%、1 種類×8枚に積むと 70.6%）。 枚数の多い順＝もう撮らなくていい見た目が上に出ます。
一致率は最新の評価実行の手動座標での成績で、評価を回すまでは空欄になります。 この表は「誰が登録したか」（API / UI）とは別で、どの画面を写したものかで束ねています。 次に撮るべきなのはここに無い見た目なので、この表には出せません。 特定の中継だけ読み切りたいときだけ、その見た目を 3〜5 枚まで積む価値があります。
手動 = 保存してある盤面座標を与えたときの認識率（認識器そのものの成績）。 自動 = 検出から通した端から端まで。盤面を検出できなかった局面は 0/81 として数えます。
大きい数字は全81マスの一致（空マス込み）、下の 駒 ○○% は 正解が駒のマスだけの向き・駒種の一致。マスの約6割は空で空判定はほぼ当たるので、 全マスのほうは駒の成績が薄まります。版どうしの比較は駒の側を見てください。
外部（ikkyoku など）から訓練データを登録するための口です。 登録された局面は履歴に 未確認 として入り、 解析タブで一度内容を確認して保存し直すまで学習には使われません。
オフの間は /api/status が enabled: false を返し、登録は 503 で断ります。
オフなら 127.0.0.1 からのみ。オンにしても外から触れるのは /api/status と /api/register だけで、 学習・削除・セッション系は常にローカル限定です。
ローカルからのアクセスには要求しません（この画面が動かなくなるため）。
登録リクエストの形式 
POST /api/register   multipart/form-data
  image        画像ファイル（PNG / JPEG）
  sfen         正解の SFEN（盤面部分だけでも可）
               ※手前側を先手として表現すること。実際の対局で後手が手前でも同じ。
                 これを外すと学習データの向き正規化が狂います
  x1,y1,x2,y2  盤面の外枠座標（必須）

Authorization: Bearer <token>   ※トークンを要求する設定のとき

200  {"status":"ok","id":"...","verified":false,"entries":12}
200  {"status":"ok","id":"...","duplicate":true}   同じ画像の再送
400  座標が無い / 画像が壊れている
401  トークンが不正
503  API 登録が無効
507  履歴が上限（古い局面は消しません）
行をクリックすると学習に使う局面として選べます（「選択した局面で学習」）。 ラベルを直すときは行末の「再入力」から解析タブへ。 盤の見た目の判定は見た目タブで行います。
同じ中継・同じゲーム画面には同じ名前を付けてください（対局名ではなく画面の見た目で分けます）。 判定そのものは認識率を上げませんが、「初めて見る盤に対する実力」を測るのに要ります （評価タブの「見た目LOO」）。目標はどんな盤でも読むことなので、 集めるべきは同じ見た目の枚数ではなく種類です。
